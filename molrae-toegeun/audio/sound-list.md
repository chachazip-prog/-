# 몰래퇴근 사운드 목록 (T-113, 1차 효과음 세트)

> 이 파일은 `audio/tools/build.py`가 자동 생성합니다. 직접 고치지 말고 `audio/src/sound-list.template.md` 또는 `audio/src/*.json`을 고친 뒤 다시 빌드하세요.

- 작성: mt-sound-designer / 2026-11-22
- 방식: 전부 코드로 합성한 오리지널 사운드입니다(오실레이터, 노이즈, 엔벨로프, 포먼트 가산 합성). **외부 에셋은 0건**이라 `compliance/asset-license-ledger.md`에 추가할 항목이 없습니다.
- 재생성: `python3 -I molrae-toegeun/audio/tools/build.py` (약 6초). 시드를 고정하고 ffmpeg `-bitexact`로 인코딩하므로 WAV, MP3, 이 문서까지 바이트 단위로 같게 나옵니다(2회 빌드 해시 비교로 확인).
- 의존성: Python 3 표준 라이브러리, ffmpeg(libmp3lame). ffmpeg가 없으면 WAV만 만들고 경고를 냅니다(`audio/build/wav/`).
- 형식(D-063, T-137): **MP3 단일 포맷**, 모노 22,050Hz, LAME VBR입니다. 효과음은 `-q:a 7`, BGM `main`은 `-q:a 8`, `tension`은 `-q:a 9`입니다. OGG는 만들지 않으며, iOS와 안드로이드 WebView 모두 MP3를 재생합니다. 빌드할 때 매니페스트에 없는 오디오 파일(예전 OGG 등)은 자동으로 지웁니다.
- 오디오 전체 용량: 효과음 72.4 KB + BGM 117.0 KB = **189.4 KB** (목표 200 KB 이하, 1KB = 1,024바이트). 빌드 스크립트가 효과음 개당 20KB, BGM 합계 300KB, 전체 200KB를 넘으면 실패로 끝냅니다.
- 엔진용 메타데이터: `game/assets/audio/audio-manifest.json` (키, 파일, 길이, 루프, 재생 조건, 시각 신호, BGM 단계)

### 발소리 3단계(본부장·대표님 접근)
| 단계 | 키 | 피크 | 음색 | 권장 조건 (화살표 크기 3단계와 같게) |
|---|---|---|---|---|
| 1 멀리 | `sfx_footsteps_1` | -11dBFS | 로우패스 1.8kHz, 둔탁 | approaching, 경로 7타일 이상 |
| 2 중간 | `sfx_footsteps_2` | -6.5dBFS | 로우패스 2.6kHz | approaching, 경로 4~6타일 |
| 3 가까움 | `sfx_footsteps_3` | -1dBFS | 필터 없음, 또각 | 경로 3타일 이하, 화면 진입 직전 |

- 세 파일 모두 0.8초(2보) 루프이고 같은 박자라서, 단계가 바뀌면 같은 재생 위치(`seek`)에서 0.15초 크로스페이드하면 자연스럽게 커집니다.
- 볼륨 차이와 함께 밝기(고음 성분)도 달라집니다. 그래서 폰 볼륨을 크게 올려도 '멀다/가깝다'가 구분됩니다.

## 2. BGM `bgm_office` (칩튠, 120bpm, 16.0초 루프)

| 키 | 스템 | 길이(초) | 루프 | 인코딩 | MP3(KB) |
|---|---|---|---|---|---|
| `bgm_office_main` | main | 16.00 | O | VBR q8 | 56.4 |
| `bgm_office_tension` | tension | 16.00 | O | VBR q9 | 60.5 |
| 합계 | | | | | 117.0 |

- 구성: `main`(살금살금 스타카토 리드, 계단 삼각파 베이스, 엇박 화음 스탭, 가벼운 하이햇)과 `tension`(16분 하이햇, 16분 아르페지오, 백비트 스네어, 4박 킥)입니다. 둘은 샘플 단위로 길이가 같습니다.
- 꼬리 음을 루프 앞쪽에 접어 넣어서(`fold_loop`) 이음새에 끊김이나 클릭이 없습니다(이음새 점프 0.015, 평균 샘플 변화량 0.007 수준).
- 루프 길이(8마디): 전체 200KB 목표(D-063)에 맞추려고 16마디(32초)를 8마디(16초)로 줄였습니다(1~8마디, Am→E로 끝나 다시 Am으로 해결). 16마디를 유지하면 두 스템을 16kbps CBR까지 낮춰야 하고, 그래도 합계가 약 210KB라서 tension의 하이햇과 아르페지오가 뭉개집니다. `audio/src/bgm.json`의 `bars`를 16으로 바꾸면 32초 버전이 다시 만들어집니다(이 경우 전체 200KB 검사에서 실패).
- 디코딩 길이: 두 스템 모두 MP3를 디코딩한 길이가 원본 WAV와 샘플 단위로 같습니다(LAME/Info 헤더의 지연·패딩 정보 기준, ffmpeg로 측정).

### 위험 단계 파라미터 (`audio/src/bgm.json` → manifest `bgm.bgm_office.stages`)

| 단계 | rate | main 볼륨 | tension 볼륨 | 전환(초) | 조건 |
|---|---|---|---|---|---|
| `calm` | 1.00 | 0.60 | 0.00 | 0.8 | 기본(위협 없음) |
| `alert` | 1.06 | 0.60 | 0.35 | 0.5 | 화면 밖 approaching 화살표가 1개 이상 또는 의심 >= 0.4 |
| `finale` | 1.12 | 0.60 | 0.45 | 0.5 | 퇴근 피날레(17:48~) 기본 단계. 위 조건이 더 높으면 danger |
| `danger` | 1.12 | 0.60 | 0.55 | 0.3 | turning(전조 중·나를 덮을 수 있음) 또는 seeing 또는 의심 >= 0.7 |
| `freeze` | 정지 | - | - | 페이드아웃 0.08 | 대표님 순시 전조(bgm: stop, sfx_elevator_ding과 같은 프레임) ~ 퇴장 후 하위 상사 복귀(1.0초 뒤) |
| `stopped` | 정지 | - | - | 페이드아웃 0.00 | 적발 컷인(sfx_caught) / 퇴근 성공(0.2초 페이드 후 sfx_clockout_fanfare) |

- 단계 우선순위: `stopped > freeze > danger > finale > alert > calm`. 올릴 때는 즉시, 내릴 때는 조건이 1.5초 이어서 풀린 뒤에 내립니다(`hysteresis.downgradeDelaySec`).
- 템포는 두 스템 공통 `playbackRate`로 올립니다. 음높이도 같이 올라갑니다(1.06배 = 약 1반음, 1.12배 = 약 2반음). 칩튠의 '서둘러!' 연출로 의도한 것입니다. 피치를 유지한 템포 변경은 웹에서 실시간으로 처리하기 어려워 쓰지 않습니다.
- 레이어는 `tension` 스템 볼륨으로 올립니다. 두 스템은 항상 같이 재생하고(`tension`은 볼륨 0으로 시작), 같은 rate를 적용해야 박자가 어긋나지 않습니다.
- 단계 조건(`when`)은 사운드 쪽 제안입니다. 최종 조건은 기획(`rules.threat.stages`)과 개발이 정하면 됩니다.

핵심 전조 9종 특징 거리(작을수록 비슷함, 대역 비율·길이·어택 수·음정성 기준). 가장 가까운 5쌍:

- `sfx_footstep_stop` - `sfx_gate_beep`: 0.47
- `sfx_footstep_stop` - `sfx_hey`: 0.48
- `sfx_chair_creak` - `sfx_hey`: 0.49
- `sfx_chair_creak` - `sfx_look_swish`: 0.49

- 대표님 전조는 'BGM이 갑자기 끊기는 것' 자체가 가장 강한 신호입니다. 그래서 `띵`은 BGM과 같은 프레임에 재생하고, BGM은 0.08초 만에 끕니다.
- 발소리 1단계는 일부러 작게(-11dBFS) 만들어 폰 잔존이 -8dB입니다. 멀리 있다는 뜻이므로 의도한 값이고, 화살표 '소'가 같이 뜹니다.
- 한계: 위 측정은 수치 근사입니다. 실기기(소형 스피커, 볼륨 30%)에서 오너 청취 확인이 필요합니다(QA 항목).

- 로드: `this.load.audio(key, ['audio/sfx/<key>.mp3'])`(MP3 단일 포맷). 경로와 루프 정보는 `audio-manifest.json`에서 읽으면 키를 하드코딩하지 않아도 됩니다.
- 루프 파일(발소리 3종, 의심 루프, BGM 2스템)은 MP3 디코딩 길이가 원본과 샘플 단위로 같습니다(LAME 헤더 기준, ffmpeg로 측정). 브라우저가 이 헤더를 무시하면 앞뒤에 무음 수십 ms가 생길 수 있으니 iOS·안드로이드 실기기에서 이음새를 확인해야 합니다. 그때는 manifest의 `durationSec`로 marker 루프(`{start: 0, duration}`)를 쓰면 됩니다.
- 모바일 자동재생 정책 때문에 첫 터치 뒤에 오디오 컨텍스트를 깨워야 합니다(Phaser `sound.unlock`).
- 볼륨: 효과음은 피크 -1dBFS 기준으로 정규화되어 있고, 탭은 -9dB, 위장 전환은 -3dB로 일부러 작게 만들었습니다. 마스터 기준으로 BGM 0.6, 효과음 1.0을 권장합니다.
- 설정: 무음과 진동 토글은 개발 범위입니다(GDD §15).

## 6. 변환 계획과 남은 일
- 웹 압축 포맷(MP3) 변환은 완료했습니다(ffmpeg를 쓸 수 있음). ffmpeg가 없는 환경에서는 WAV만 만들어지므로 ffmpeg가 있는 곳에서 같은 스크립트를 다시 돌리면 됩니다.
- 2차 후보(데이터에 키가 없어 이번에는 만들지 않음): 간식 '바삭'과 '바스락!!', 커피 따르기, 낮잠 '쿵', 쇼핑 결제, 가방 챙기기, 인사 QTE '?'와 '!', 공범 경고 헛기침(지금은 `sfx_cough`를 재사용 가능), 출근 징글, 메뉴 BGM.
