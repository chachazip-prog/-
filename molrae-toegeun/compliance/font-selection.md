## 3. 서브셋 + 비트맵 폰트(BMFont) 변환과 라이선스

### 3.1 OFL 기준 정리

| 질문 | 답 | 근거 | 구분 |
|---|---|---|---|
| 필요한 글자만 남기는 서브셋은 수정인가? | 수정 버전(Modified Version)으로 다룸 | OFL FAQ: 폰트 데이터를 바꾸는 재빌드는 모두 수정 버전. 서브셋도 안전하다고 보지 않음 | [확인] |
| 포맷 변환(TTF → WOFF2, BMFont PNG+.fnt)은 수정인가? | 수정 버전으로 다룸. 압축만 하고 데이터와 고지를 그대로 둔 WOFF만 예외 | OFL FAQ (WOFF 항목, SVG 변환 항목) | [확인] |
| 수정 버전을 게임에 넣어 배포해도 되나? | **됨.** 조건: ① RFN 미사용 ② 원 저작권 고지와 OFL 전문 동봉 ③ 수정본도 OFL ④ 폰트 단독 판매 금지 | OFL 1.1 본문 조건 1~5 | [확인] |
| 게임 번들 자체가 허용되나? | 됨. 게임은 OFL FAQ의 번들 허용 사례 | OFL FAQ | [확인] |
| 게임 코드·아트도 OFL이 되나? | 안 됨. 폰트를 번들·임베딩해도 다른 저작물의 라이선스는 바뀌지 않음 | OFL 조건 5, FAQ | [확인] |
| 폰트로 렌더링한 이미지(예: 글자가 박힌 버튼 PNG)는? | OFL 적용 대상이 아님 | OFL FAQ: 폰트로 만든 그래픽은 OFL 대상이 아님 | [확인] |
| BMFont 아틀라스(글리프 PNG + .fnt 좌표표)는 '그래픽'인가 '폰트'인가? | 문자 단위로 재조합해 쓰는 폰트 데이터이므로 **수정 버전(폰트)으로 보고 OFL 조건을 지키는 것이 안전함** | OFL FAQ에 게임용 비트맵 아틀라스를 직접 다룬 항목은 찾지 못함 | [추정]. 보수적으로 처리 |

### 3.2 우리 프로젝트 적용 규칙 (Galmuri 채택 시)

1. **파생 폰트 이름을 바꿉니다.** BMFont의 `info face=` 값, 파일명, Phaser 로드 키에 "Galmuri"를 쓰지 않습니다. 예: `mt-pixel-12`, `mt-pixel-10`, `mt-pixel-8`. (이름은 PM 결정)
   - (2026-11-22 정정) Galmuri는 RFN 선언이 없어 이 규칙은 **OFL 의무가 아니라 내부 보수 규칙**입니다(D-046). 다만 OFL 조건 4(저작자 이름을 수정본 홍보에 쓰지 않음)는 그대로 적용되므로, 홍보 문구에 "Galmuri 사용" 식 표현을 쓰지 않는 것이 안전합니다 [추정]. 고지 파일의 출처 표기는 허용 [확인](조건 4 단서).
   - 구현 확인: 변환물 `info.face` = `mt-pixel-12/10/8` [확인].
   - 코드 주석이나 라이선스 고지에 "Galmuri에서 파생됨"이라고 **출처를 밝히는 것은 RFN 위반이 아닙니다** [추정]. RFN은 파생 폰트의 *이름*으로 쓰는 것을 막는 조항입니다.
2. **고지를 함께 배포합니다.** 빌드 산출물(`dist/`)에 `licenses/OFL-galmuri.txt`(원 저작권 줄 + OFL 1.1 전문)를 넣습니다. 게임 안 '정보 → 오픈소스 라이선스' 화면에도 같은 내용을 보여 줍니다.
   - OFL은 고지를 "독립 텍스트 파일, 사람이 읽을 수 있는 헤더, 또는 기계가 읽는 메타데이터 필드" 중 하나로 동봉하도록 요구합니다 [확인]. BMFont .fnt에는 메타데이터 필드가 없으므로 텍스트 파일로 동봉합니다.
3. **파생물은 OFL로 둡니다.** 변환한 `.fnt`·`.png`·서브셋 WOFF2를 게임의 다른 라이선스로 묶지 않습니다. 대장에도 OFL-1.1로 기록합니다.
4. **원본 사본과 변환 스크립트를 보관합니다.** 원본 TTF/BDF의 버전(태그), 받은 날짜, 변환 스크립트 경로, 글자 목록을 기록해 재현할 수 있게 합니다.
5. **폰트 단독 판매나 단독 배포는 하지 않습니다.** 앱인토스 번들 안에서만 씁니다.

### 3.3 웹폰트(서브셋 WOFF2) 방식과 BMFont 방식 비교 (참고, 결정은 개발·PM)

| 방식 | 장점 | 단점 | 라이선스 |
|---|---|---|---|
| A. BMFont(PNG + .fnt) + Phaser BitmapText | 정수 배율에서 픽셀이 정확함. 렌더링 흐림 없음. 용량 작음(아래) | 대사를 추가할 때마다 아틀라스를 다시 만들어야 함 | 수정 버전. §3.2 적용 |
| B. 서브셋 WOFF2 + Phaser Text(캔버스) | 글자 추가가 쉬움 | 브라우저 안티앨리어싱 때문에 다시 흐려질 수 있음. 해결하려면 별도 처리 필요 | 수정 버전. §3.2 적용 |

- 용량 [추정]: 12px 글리프 약 500자를 넣으면 대략 12×12×500 ≈ 72,000픽셀이라 256×512 아틀라스 1장 안에 들어갑니다. 1비트에 가까운 PNG라 수십 KB 이하로 예상합니다. 11,172자 전체 웹폰트를 넣을 때(수백 KB~MB급)에 비해 D-019의 2MB 목표에 부담이 없습니다.

## 4. 구현 측 권고 (개발·QA 전달용, 라이선스와 직결되는 것만)

- **글자 목록 자동 추출과 누락 검사**: `game/data/*.json`과 UI 문자열에서 사용 글자를 뽑아 서브셋을 만들고, **원 폰트에 없는 글자가 있으면 빌드를 실패**시킵니다. 이렇게 하면 Galmuri 크기별 수록 범위 문제(§2.1 [확인 필요])가 자동으로 잡힙니다.
- 대체 글리프를 다른 폰트에서 가져와 섞지 않습니다. 섞어야 한다면 그 폰트도 대장에 따로 등록하고 라이선스 호환성을 확인합니다(OFL끼리는 합칠 수 있지만 RFN은 각각 지켜야 함 [확인]).
- 변환 도구(예: BMFont 생성기, fonttools)도 라이브러리라 빌드에 포함되지 않더라도 대장에 LIB 항목으로 기록하는 것을 권장합니다(도구 라이선스가 산출물을 제약하지 않는지 확인).

## 5. 채택 시 절차 (후보 → 승인)

1. PM이 1순위를 확정합니다(§6).
2. 아트 또는 개발이 원 저장소의 **릴리스 태그**에서 폰트와 `ofl.md`를 받습니다(오너 또는 담당 에이전트가 진행. 컴플라이언스는 다운로드하지 않음).
3. 컴플라이언스가 받은 `ofl.md`에서 다음을 확인하고, [확인 필요] 항목을 [확인]으로 바꿉니다.
   - 저작권 줄
   - RFN 문구
   - README의 한글 음절 수록 범위(크기별)
4. 라이선스 사본을 `art/licenses/`(또는 PM이 정한 위치)에 저장하고, 대장의 '라이선스 사본' 칸을 채웁니다.
5. 변환물 이름(RFN 회피), 고지 파일 동봉, 정보 화면 고지를 확인한 뒤 대장 상태를 `승인`으로 바꿉니다.

## 6. PM 결정이 필요한 사항

```
[결정 필요] 한글 도트 폰트 채택
- 배경: 시스템 폰트가 흐려서 T-119가 우선순위 상향됨. 1순위 Galmuri(OFL 1.1, 8·10·12px)
- 선택지: A. Galmuri 단일 패밀리 / B. Fusion Pixel KR / C. Galmuri 본문 + Neo둥근모 타이틀
- 추천: A. 크기 세 종이 한 패밀리에 있어 톤이 통일되고 라이선스가 하나라 관리가 단순함.
  C는 타이틀 느낌을 원할 때만 고려(라이선스 고지 2건)
- 기한: game/src/scenes/style.ts 임시 폰트 교체, 아트 UI 작업
```

그 밖에 PM이 정할 것:
1. **크기 조합**: 대사 12px(Galmuri11), 라벨 10px(Galmuri9), 숫자 8px(Galmuri7) 중 무엇을 쓸지. 8px 한글은 읽기 어려울 수 있으니 8px는 숫자·영문 전용을 권장합니다 [추정].
2. **렌더링 방식**: BMFont(A) 또는 서브셋 WOFF2(B) (§3.3). 라이선스상 둘 다 가능합니다.
3. **파생 폰트 이름**: RFN 회피용 이름(예: `mt-pixel-12`).
4. **고지 위치**: 게임 안 '정보 → 오픈소스 라이선스' 화면을 만들지 여부. 라이브러리(Phaser MIT 등) 고지도 어차피 필요하므로 한 화면으로 통합하는 것을 권장합니다.
5. **원본 수령 담당**: 아트(mt-pixel-artist)와 개발(mt-client-dev) 중 누가 받고 변환 스크립트를 소유할지.
