# 화면 해상도·배율 결정 (T-102)

- **논리 해상도: 180×320 (9:16, 세로 고정)**
- **배율: 정수 배율만 사용** — `floor(min(부모너비/180, 부모높이/320))`, 최소 1. 리사이즈 시 재계산 (`src/config/display.ts`, `src/main.ts`).
- 남는 영역은 배경색(#1b1b22) 레터박스. `pixelArt: true`, `roundPixels: true`, CSS `image-rendering: pixelated`.

## 근거
1. 주요 폰의 CSS 너비가 360(안드로이드 다수)·375·390·393·412·430px → 모두 **2배(360×640 CSS px)**가 들어감. 360폭 기기에서는 좌우 여백 0.
2. DPR 3 기기에서 2배 × 3 = 실제 6배(1080×1920 디바이스 px)로 정수 매핑되어 도트가 번지지 않음.
3. 180×320은 16px 타일 기준 가로 11.25칸 / 8px 기준 22.5×40칸 — 사무실 한 줄(책상·상사 동선, D-001 좌우 1축)을 담기에 충분하면서 스프라이트 제작량이 적음.
4. 하위 기기·태블릿(예: 768×1024 CSS)은 3배로 커짐.

## 알려진 한계
- 19.5:9 기기(예: 390×844)는 640px 높이만 쓰고 위아래 약 100px씩 레터박스. 필요하면 추후 "가로 180 고정 + 세로 320~390 가변" 방식으로 확장(레이아웃을 세로 가변 대응으로 작성해야 함).
- 텍스트는 도트 비트맵 폰트(T-126, D-042): `mt-pixel-12`(대사·UI) / `mt-pixel-10`(라벨) / `mt-pixel-8`(숫자·영문 전용). Galmuri 2.40.3(OFL 1.1) 서브셋 변환물. 생성 `npm run fonts`(scripts/build-fonts.ts, `npm run build`에 포함), 사용 `src/ui/pixelText.ts`. 크게 쓸 때는 정수 배율(scale 2, 3)만. 고지 `public/licenses/OFL-galmuri.txt`.
- 토스 내비게이션 바·세이프 에어리어 높이만큼 가용 높이가 줄 수 있음(SDK `getSafeAreaInsets` 존재, 미연동).
