## 1. 공통 가정

### 1-1. 매출 산식 [추정]
- 월 매출 = DAU × ARPDAU × 30일. **수수료 차감 전** 금액입니다.
- 1인 일평균 판수는 5판으로 가정합니다(KPI의 Go 기준값). 전면광고는 하루 평균 0.7회, 보상형은 DAU 1인당 0.45회(시청률 30% × 1.5회)로 잡았습니다.
- eCPM 가정(앱인토스 실측치가 없어 일반론 기준): 전면 3,000~8,000원, 보상형 8,000~20,000원, 배너 300~1,000원입니다. 앱인토스 콘솔의 인앱 광고 분석 탭에서 유형별 eCPM을 볼 수 있으므로(SDK 2.7.0 이상) [확인], **출시 2주 뒤 실측치로 이 표를 갱신**합니다.
- 이 가정으로 광고만 계산하면 ARPDAU는 약 6~15원입니다. D-006의 보수 기준 10원은 이 범위 안에 있습니다.
- **fill 리스크(토스앱 버전)**: 광고 2.0 ver2는 토스앱 5.247.0 이상에서만 지원되고, 5.227 이상 5.247 미만에서는 AdMob만 송출됩니다 [확인, PM 공지].
  - 위 eCPM 가정은 fill률 100%를 전제로 합니다. 구버전 사용자 비중이 크면 실제 광고 ARPDAU는 그 비중만큼 낮아질 수 있습니다. 예: 구버전 20%, 그 구간의 eCPM·fill 절반이면 약 10% 감소 [추정].
  - 대응: 광고가 로드되지 않으면 결과로 바로 넘어가게 합니다(§4-2). 출시 뒤 콘솔에서 앱 버전별 fill률을 확인하고, 매출표의 **보수 열**을 기본 판단치로 씁니다.

### 1-2. 수수료 [확인 필요]
- 인앱결제·인앱광고·토스 홈 광고의 수수료 무료 프로모션은 2026-02-28까지였고, 이후 요율은 "별도 안내"라고만 되어 있습니다 [확인]. 현재 요율은 검색으로 확인하지 못했습니다.
- 개인 개발자 회고에는 "광고 매출의 약 30%를 송출 운영비로 공제한다"는 언급이 있습니다. 개인 후기라 참고만 합니다 [확인 필요].
- 아래 표의 실수령액은 **매출 × 0.7**을 보수적인 참고치로 씁니다. 오너가 콘솔 정산 약관에서 실제 요율을 확인해야 합니다.

### 2-3. S1 광고 Only

**구조**
- 보상형(이어하기, 월급 2배, CEO 순시 패스)과 예고형 전면광고로 구성합니다.
- 변형 S1b는 로비·도감 화면에 배너를 추가합니다.

**장점**
- 인앱결제 연동, 상품 등록, 구매 복원, 환불 대응이 모두 필요 없습니다. 개발량과 운영 부담이 가장 적습니다.
- 사업자 없이도 누적 5천 원까지는 광고를 붙일 수 있습니다. 2026-08-28 시행 [확인].
- 유료 상품이 없어 유저 피해 대응 정책상 환불 리스크가 거의 없습니다. Kill 판정 뒤 방치 운영으로 바꾸기도 가장 쉽습니다.
- "돈 내면 편해지는 게임"이라는 인상이 없습니다. 공감 코미디 톤과도 맞습니다.

**단점과 리스크**
- **광고를 끌 방법이 없습니다.** 하루 5판 이상 하는 헤비 유저일수록 전면광고를 많이 봅니다. 이들이 리뷰와 문의로 불만을 표출하고 먼저 이탈합니다 [추정].
- 헤비 유저는 "돈 주고라도 끄고 싶은" 층입니다. S1에서는 이 지불 의사를 매출로 받을 수단이 없습니다.
- 매출이 광고 수요(eCPM)에 100% 걸려 있습니다. 연말·연초 광고 단가가 바뀌면 매출이 그대로 흔들립니다.

**광고 제거 수단이 없을 때 쓸 완화책**
1. **전면 빈도를 유저의 숙련도에 맞춰 줄입니다.** 첫날은 전면을 0회로 둡니다. 2일차부터 3판에 1회, 하루 5회 상한을 적용합니다(§4-2).
2. **보상형 시청을 전면 면제권으로 씁니다.** 그 판에서 보상형 광고를 봤다면 다음 전면 카운터를 초기화합니다. 유저가 광고 종류를 스스로 고르는 셈입니다.
3. **매출 비중을 보상형으로 옮깁니다.**
   - 보상형 eCPM이 전면보다 높다는 가정 [추정]에서는, 전면을 줄이고 보상형 지점을 늘려도 매출이 크게 줄지 않습니다.
   - 늘릴 지점 후보는 출근 도장 2배, 도감 힌트 같은 선택형 보상입니다.
4. **"오늘은 여기까지" 연출을 둡니다.** 전면 하루 상한에 도달하면 "오늘 광고는 끝! 남은 판은 광고 없이 즐기세요" 토스트를 띄웁니다. 상한이 있다는 사실이 불만을 줄입니다 [추정].
5. **광고 고지 문구를 톤에 맞춥니다.** 예: "잠깐, 팀장님이 지나가는 동안 광고 한 편". 단, 광고가 나온다는 사실은 반드시 명확하게 알립니다.
6. **S2로 넘어갈 신호를 정해 둡니다.** 출시 2주 안에 문의·리뷰에서 "광고가 많다"는 지적이 반복되거나, 하루 10판 이상 하는 유저의 비율이 높게 나오면 광고 제거 IAP를 붙입니다.

**배너 포함(S1b) 판단**
- **MVP에서는 넣지 않는 것을 추천합니다.**
  - 세로형 도트 플레이 화면이 작아지고, 결과 공유 카드와 겹칠 수 있습니다.
  - 매출 증가분은 1인당 하루 2~5원 수준으로 추정합니다.
  - 토스애즈 리스트배너가 2026-10-26부터 새 디자인으로 바뀌었고 WebView SDK 3.0.5 이상에서만 송출됩니다 [확인]. 넣는다면 SDK 버전부터 확인해야 합니다.
- 넣는다면 로비와 도감 화면에만 둡니다. 플레이 화면과 결과 공유 카드에는 넣지 않습니다.

### 2-4. S2 광고 + 광고 제거 IAP (현 기본안)

**구조**
- S1a에 비소모성 IAP '광고 제거'를 더합니다. 앱인토스 인앱결제는 소모성·비소모성·구독 상품 유형을 지원합니다 [확인. 개발자센터 getProductItemList 문서 검색 결과].
- **제거 범위: 전면광고(와 배너)만 제거하고, 보상형은 선택형으로 남깁니다.** 상품 설명에 이 범위를 명시해야 과장 표시 분쟁이 생기지 않습니다.

**가격과 카니발리제이션**
- 하루 5판 하는 유저의 전면광고 가치는 하루 약 3~5원입니다(0.7~1회 × eCPM 3,000~8,000원 ÷ 1,000) [추정].
- 그러면 2,900원은 그 유저의 전면광고 매출 약 1.5~2.5년치입니다. **구매가 일어날 때마다 순이익입니다.**
- 구매 전환은 DAU 기준 하루 0.03~0.1%로 가정합니다 [추정]. 이 경우 ARPDAU는 1~3원 늘어납니다.

**구현에 필요한 것**
- 결제 API 연동과 구매 상태 저장(Storage)이 필요합니다.
- 비소모성이라 구매 복원이 필수입니다. 기기를 바꾸거나 Storage가 유실되는 경우에 대비해야 합니다 [추정. 앱인토스의 복원 방식은 개발에서 확인 필요].
- 환불 문의 대응 절차가 있어야 합니다(유저 피해 대응 정책).

**리스크**
- 사업자가 없으면 상품을 팔 수 없습니다 [확인].
- 서비스를 종료할 때 영구 상품 구매자 처리 방식을 정해야 합니다. 종료 시 의무와 유저 피해 대응 정책에 동의해야 종료할 수 있습니다 [확인]. 영구 상품 구매자에게 환불이 필요한지는 [확인 필요]입니다.

### 2-5. S3 광고 + 코스메틱 IAP

**구조**
- 직군 스킨, 책상 테마, 의자, 머그컵 같은 소품을 직접 구매합니다. **뽑기와 랜덤 박스는 넣지 않습니다**(D-004).
- 가격 후보는 1,100~2,200원 단품과 3,300~4,400원 번들입니다 [추정].

**판단**
- 매출 증가분은 작습니다(+1~4원). 반면 아트 물량(스킨 1종당 4상태 애니메이션)과 상점 UI가 필요합니다.
- Go 판정(D7 10% 이상) 뒤 2차 범위로 두는 기존 계획이 맞습니다.

**설계 원칙**
- 코스메틱은 **성능에 영향을 주지 않습니다.** 의심 게이지나 이동 속도 같은 능력치를 붙이면 페이투윈이 되어 D-005의 취지에 어긋납니다.
- 일부 스킨은 **무료 획득 경로**를 둡니다. 승진 달성, 도감 완성, 시즌 출석이 그 예입니다. 무료 유저도 수집 동기를 갖게 하려는 것이고, 공유 카드에 스킨이 노출되면 바이럴 소재가 됩니다.
- 시즌 테마는 서버 없이 날짜 조건만으로 판매 기간을 엽니다. 예: 12월 '연말 회식 넥타이', 설 연휴 '귀성 캐리어'. 서버 시간 API를 쓸 수 있으면 클라이언트 시간 대신 그것을 씁니다 [확인. 게임 SDK 가이드에 서버 시간 API 안내].

### 2-6. S4 광고 + 시즌패스/후원형

**시즌패스 (가능성: 높음, 단 2차 이후)**
- 앱인토스 인앱결제에는 구독 상품 유형과 구독 주문 생성·상태 조회 함수가 있습니다 [확인. 개발자센터 subscription 문서].
- 다만 구독형 패스는 자동 갱신, 해지, 환불 대응이 무겁습니다. 1인 개발 체제에서는 권하지 않습니다.
- 현실적인 형태는 **'시즌 비소모성 상품'**입니다. 예: "겨울 시즌 사원증", 4~6주 한정.
  - 진행도는 로컬 Storage로 관리하고, 시즌 기간은 날짜 조건으로 정합니다.
  - 보상은 확정 보상(코스메틱, 칭호)만 줍니다. 랜덤 보상과 토스포인트 보상은 금지입니다(D-004).
- 리스크
  - 시즌 도중 서비스를 종료하면 환불 요청이 들어올 가능성이 큽니다(유저 피해 대응 정책).
  - 매 시즌 콘텐츠를 만들 부담이 있습니다.
  - "숙제" 느낌이 생기면 '숨 돌리기' 톤과 충돌합니다.

**후원형 "팀장님 몰래 커피 한 잔" (가능성: 확인 필요)**
- 대가 없는 순수 후원·기부형 상품을 앱인토스 인앱결제로 팔 수 있는지는 **검색으로 확인하지 못했습니다** [확인 필요].
- 앱마켓에서는 일반적으로 디지털 재화나 기능을 제공하는 상품 구조를 요구합니다 [추정].
- 우회안은 **후원 + 확정 코스메틱 상품**입니다. 예: "커피 한 잔 사주기(1,100원): 책상에 '감사 머그컵' 소품 + 크레딧 화면 '고마운 동료' 칭호". 이렇게 하면 후원 성격의 비소모성 상품이 됩니다. 이 형태가 허용되는지도 컴플라이언스가 확인해야 합니다.
- 기대 매출은 낮습니다(+0.5~1원). 유저 심리상 "만든 사람을 응원하는" 맥락이 있어야 작동하므로, 출시 초기보다 일정 팬층이 생긴 뒤에 맞습니다 [추정].

- 보상 조건(무엇을, 몇 번)은 광고 버튼에 **미리** 표시합니다. 시청을 완료했을 때만 지급하고, 중간에 닫으면 지급하지 않되 불이익도 주지 않습니다.
- 보상은 모두 확정값입니다. "광고 보고 랜덤 상자"는 금지합니다(D-004).

### 4-2. 전면광고 빈도 규칙

| 규칙 | 값 (추천) | 비고 |
|---|---|---|
| 노출 시점 | 판이 끝난 뒤, **결과 화면에 들어가기 직전**에만 | 플레이 중, 앱 시작 직후, 일시정지, 메뉴 이동 중에는 노출하지 않습니다 |
| 예고 | 판 종료 연출 중에 "광고 1편 뒤 결과를 보여드려요"를 1~2초 표시 | UX 원칙 "시점을 알리기" |
| 광고 후 | **바로 결과 화면.** 이어서 다른 광고(보상형 제안 팝업 포함)를 자동으로 띄우지 않습니다 | UX 원칙 "반복 금지". R2 버튼은 결과 화면 안의 선택 버튼으로만 둡니다 |
| 빈도 | 3판 완료당 1회 | 기존 안 유지 |
| 첫 세션 보호 | **설치 첫날(로컬 날짜 기준) 0회.** 2일차부터 적용하되, 누적 첫 5판은 면제 | 기존 "첫 5판 면제"를 강화한 안. 첫날 이탈 방지가 D1 리텐션과 추천 선정에 직결됩니다 [추정] |
| 보상형과의 관계 | 그 판에서 보상형(R1~R3)을 봤다면 전면 카운터를 0으로 초기화 | 광고가 연달아 나오는 것을 방지합니다 |
| 이어하기 직후 | R1을 본 판의 종료 시점에는 전면을 띄우지 않습니다 | 같은 판에 광고 2회 금지 |
| 최소 간격 | 직전 광고(종류 무관)에서 3분 | 짧은 판을 연속으로 해도 광고가 몰리지 않게 합니다 |
| 하루 상한 | **5회** | 기존 5~6회에서 하한을 택했습니다. 광고 빈도 변경은 오너 승인 사항입니다 |
| 상한 도달 시 | "오늘 광고는 끝! 남은 판은 광고 없이" 토스트 1회 | 불만 완화 |
| 광고 로드 실패 | 그냥 결과로 넘어갑니다. 재시도나 대기는 하지 않습니다 | |
| 광고 제거 구매자 | 전면(과 배너) 0회. 보상형 버튼은 유지 | 상품 설명에 명시 |

### 4-3. 날짜·카운터 처리 (서버 0원)
- 일일 카운터(전면 횟수, 보상형 횟수, 출근 도장)는 Storage에 `{date, counts}`로 저장합니다. 날짜가 바뀌면 초기화합니다.
- 날짜는 앱인토스 서버 시간 API를 쓸 수 있으면 그것을 씁니다 [확인. 게임 SDK 가이드]. 쓸 수 없으면 기기 로컬 날짜를 씁니다. 기기 시간을 조작해도 광고가 덜 나오는 정도라 피해가 작습니다.
- 첫 설치 날짜를 Storage에 기록합니다. 첫날 보호에 씁니다.

## 6. PM 추천안과 오너 결정 항목

### 6-1. 마케팅 추천안 (PM 추천용): **"S1a로 출시해 승인 즉시 S2로, Go 뒤에 S3"**

출시 BM은 **보상형 + 예고형 전면, 배너 없음**으로 합니다. 사업자 승인이 끝나는 대로 **광고 제거 IAP 2,900원**을 켭니다. 출시 전에 승인되면 S2로 바로 출시합니다. 코스메틱은 Go 판정 뒤에 엽니다.

**근거**
1. **수익 차이보다 노출 차이가 큽니다.** 시나리오 간 ARPDAU 차이는 1.5~7원입니다. 반면 추천 미니앱 선정 여부는 DAU를 몇 배 바꿉니다(부스팅은 추천의 약 20배 노출 [확인]). 그래서 UX 원칙을 가장 깔끔하게 지키는 구성(배너 없음, 첫날 전면 0회)이 장기 매출에 유리합니다.
2. **광고 제거 IAP는 손해가 거의 없는 안전판입니다.** 헤비 유저의 전면광고 매출은 하루 3~5원이라 2,900원이면 1년 이상치입니다. 불만을 매출로 바꾸는 장치이므로 사업자가 나오면 바로 붙입니다.
3. **D-012, D-016과 충돌하지 않습니다.** IAP 코드는 미리 만들고 플래그로 꺼 두면 행정 일정에 개발이 묶이지 않습니다.
4. **D-006 기준을 충족합니다.** S1a의 보수 ARPDAU는 8원으로, 첫날 보호 때문에 D-006의 10원보다 약간 낮습니다. S2 기준값은 14원이라 손익 판단 기준을 넘습니다.
5. 후원형(S4)과 유료 프로모션(S5)은 허용 여부와 회수 가능성이 불확실해 보류합니다.

1. 현재 인앱광고·인앱결제 수수료율과 정산 약관
2. 후원형("커피 한 잔") 상품이 허용되는지
3. 바이럴 SDK의 출시 여부와 조건(참고용. 현재 계획은 보상 없는 공유)
4. 비소모성 상품 구매자의 서비스 종료 시 환불 의무 범위(유저 피해 대응 정책 원문)
5. D-004의 근거가 되는 프로모션 정책 원문 조항
6. 미성년자 결제와, 등급분류 신청 시 유료 아이템 표기
7. 미니앱 안에 외부 링크(굿즈)나 다른 미니앱 딥링크(크로스프로모션)를 둘 수 있는지
