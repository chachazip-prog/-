## 2. 게임 컨셉

### 2-1. 한 줄 정의
> 사무실 한 층에서 **누르고 있으면 땡땡이, 떼면 일하는 척**하는 원터치 눈치 게임입니다. 1판은 하루 근무(09:00→18:00)이고, 60~90초 동안 진행됩니다.

### 2-2. 조작 방식 결정 (세 검토 결과 조율)
게임 기획 쪽은 고정 화면에서 홀드/떼기로 조작하는 방식을, PM 쪽 WBS는 탑다운 이동·시야 콘·4방향 걷기를 전제로 했습니다. **MVP는 홀드/떼기 방식으로 정합니다.**

| 항목 | 홀드/떼기 (채택) | 탑다운 이동 스텔스 |
|---|---|---|
| 조작 | 원터치. 지하철에서 한 손으로 가능 | 가상 패드가 필요해 모바일 웹에서 불편함 |
| 도트 에셋 | 정면·측면 위주, 상태 모션 몇 개 | 캐릭터마다 4방향 걷기가 필요해 에셋이 2~3배 |
| 개발 | 게이지 + 시선 판정 공통 엔진 | 길찾기·충돌·시야 계산 |
| 확장 | 이벤트 파라미터만 바꿔 추가 | 맵마다 레벨 디자인 필요 |

탑다운 이동 요소(화장실 가기 동선 등)는 **좌·우 1축 이동**으로 단순화해 일부 이벤트에만 씁니다.

### 2-3. 핵심 루프
```
출근 → [이벤트 3~5개 + 사이사이 업무 구간] → 몰래 퇴근(최종 이벤트) → 정산(월급·★) → 승진·해금 → 다음 날
```

| 장치 | 규칙 |
|---|---|
| **홀드 / 떼기** | 누르면 땡땡이 게이지가 차고, 떼면 즉시 타이핑 자세로 돌아가 안전해집니다. |
| **의심 게이지** | 상사가 보는 중에 누르고 있으면 급상승합니다. 100%가 되면 "○○ 씨, 잠깐 나 좀 봐" 엔딩(실패)입니다. |
| **업무 게이지** | 손을 떼고 있을 때만 찹니다. 기준에 못 미치면 '야근 엔딩'(성공하되 보상 감소)입니다. 이 장치 덕분에 땡땡이와 업무 사이의 시간 배분이 전략이 됩니다. |
| **전조(tell)** | 의자 삐걱 소리, 헛기침, '…' 말풍선이 0.4~1.0초 먼저 나옵니다. 직급이 오를수록 짧아집니다. 공정성을 위해 전조는 반드시 표시합니다. |
| **페이크·콤보** | 상사가 돌아보는 척만 하거나 연속으로 돌아봅니다. 들키지 않고 연속 성공하면 보상 배수가 오릅니다. |
| **별점** | ★1 생존 / ★2 업무 기준 달성 / ★3 의심 30% 미만 |

### 2-5. 메타 진행
- **직급 승진**: 인턴(튜토리얼) → 사원 → 대리 → 과장 → 차장·부장 → 임원(엔드리스). 승진 조건은 누적 ★입니다. 실패해도 진행이 쌓이므로 하드 월이 없습니다.
- **상사 도감**: 들킨 리액션도 수집 대상이라 **실패도 콘텐츠가 됩니다.** 이 게임의 재미를 가르는 핵심 포인트입니다.
- **월급(소프트 재화)**: 책상 꾸미기, 위장 아이템(가짜 서류뭉치: 의심 -20% 등)에 씁니다.
- **실제 요일 연동**: 월요일에는 상사가 예민해지고, 금요일에는 '불금 칼퇴' 이벤트가 열리고, 18시 이후 접속하면 보너스를 줍니다. 기기 시계만 쓰므로 서버가 필요 없습니다.

### 2-6. 차별점
1. **하루 단위로 이벤트가 이어지는 구조**: 단발 퍼즐로 끝나는 기존 '몰래' 하이퍼캐주얼과 다릅니다.
2. **'일하는 척' 위장 연출**: 손을 떼면 업무 화면으로 바뀝니다. 실제 옆자리 시선까지 노린 메타 유머입니다.
3. **한국 직장 디테일**: 결재, 메신저 "잠깐 저 좀", 회식, 연말정산 같은 소재를 씁니다.

## 3. 수익화 방안

### 3-1. 추천 조합
**보상형 광고(주력) + 예고형 전면광고(빈도 제한) + 광고 제거 IAP. 배너와 코스메틱 IAP는 2차에 붙입니다.**

| 상품 | 형태 | 배치·가격 | 단계 |
|---|---|---|---|
| 들킨 직후 이어하기 | 보상형 광고 | 1판에 1회 | MVP |
| 오늘 월급 2배 | 보상형 광고 | 정산 화면 | MVP |
| 전면광고 | 전면 | **3판에 1회, 첫 5판은 면제**, 결과 화면 전에 "잠시 후 광고" 예고. 하루 최대 5~6회 | MVP |
| 광고 제거 | 비소모성 IAP | 2,900~3,900원. 전면광고만 제거하고 보상형은 유지 | MVP (사업자 등록 후) |
| 메뉴 하단 배너 | 배너 | 플레이 중에는 노출하지 않음. WebView SDK 3.0.5 이상 필요 [확인] | 2차 |
| 코스메틱 (직군·시즌 스킨, 책상 테마) | IAP | 990~4,900원. 직접 구매만 가능(랜덤 뽑기 금지) | 2차 |
| 부활권 판매 | IAP | 보상형 광고와 겹치고 페이투윈 인상을 줘서 **판매하지 않음** | - |

- **광고 UX 원칙 [확인]**: 앱인토스 추천 미니앱 기준에 "전면광고는 예고하고, 반복하지 말 것"이 있습니다. 이를 지켜야 추천 노출을 노릴 수 있습니다.
- **SDK 확인사항 [확인]**: `loadFullScreenAd`/`showFullScreenAd`로 전면광고와 보상형 광고를 모두 처리합니다. Toss Ad를 먼저 쓰고 없으면 AdMob으로 자동 전환합니다. 토스앱 5.227.0 미만은 지원하지 않으므로 `isSupported()`로 분기해야 합니다.

### 3-2. 수익 시뮬레이션 [추정]
마케팅 검토는 ARPDAU 15~45원, PM 검토는 5~15원으로 서로 달랐습니다. **손익 판단에는 보수적인 10원을 쓰고, 마케팅 수치는 상단 가능성(upside)으로만 봅니다.**

| DAU | 보수 (ARPDAU 10원) | 기준 (20원) | 낙관 (40원) |
|---|---|---|---|
| 1,000 | 월 30만 원 | 월 60만 원 | 월 120만 원 |
| 10,000 | 월 300만 원 | 월 600만 원 | 월 1,200만 원 |
| 50,000 | 월 1,500만 원 | 월 3,000만 원 | 월 6,000만 원 |

- 플랫폼 수수료와 광고 수익 배분을 빼기 전의 금액입니다. 실제 eCPM은 콘솔 광고 대시보드에서 출시 후에 확인할 수 있습니다 [확인].
- **손익분기**: 개발비 1,700만 원을 ARPDAU 10원으로 12개월 안에 회수하려면 **평균 DAU 약 4,700명**이 필요합니다. 캐주얼 게임은 출시 후 DAU가 빠르게 줄어드는 경향이 있으므로 추천 노출이나 시즌 이벤트 없이는 쉽지 않은 수치입니다.
- **운영비**: 서버, DB, CDN이 필요 없어 **월 0~1만 원**입니다. 그래서 수익이 부진해도 방치 운영하는 비용이 거의 없습니다. 이 구조의 가장 큰 장점입니다.

## 4. 서버리스 구조

```
[Phaser 3 + TypeScript 번들] → 앱인토스 콘솔 업로드·검수 → 토스 앱 WebView
  ├─ 진행 저장: Storage API (기기 로컬, JSON + 버전 키)         [확인]
  ├─ 랭킹: 토스 게임센터 리더보드 (게임 카테고리 등록 필요)       [확인]
  ├─ 광고: Toss Ad / AdMob 통합 SDK                              [확인]
  ├─ 공유 보상: 공유 리워드 SDK (조건은 콘솔에서 설정, 승인 필요)  [확인]
  └─ 레벨·이벤트: 번들 안 JSON 데이터 테이블 + 날짜 시드 생성
```

| 항목 | 결정 |
|---|---|
| 엔진 | **Phaser 3 + TS + Vite**. 가볍고 도트 표현에 적합합니다. Unity WebGL은 번들이 무겁고 로딩이 길어 제외합니다(외주 개발자가 Unity 전문인 경우만 예외). |
| 저장 | Storage API 하나로 처리합니다. 토스 앱을 지우면 데이터도 사라지므로 [확인] 진행도의 중요도를 낮게 설계하고 미리 고지합니다. |
| 콘텐츠 | `events` / `bosses` / `days` / `modifiers` / `items` 테이블을 둡니다. 수작업 레벨은 약 40~50일분만 만들고, 이후 구간과 '오늘의 출근'(날짜 시드)은 절차적으로 생성합니다. |
| 업데이트 | 번들 재검수가 필요하므로 **월 1회 이하로 모아서 배포**합니다. 시즌 이벤트는 날짜 조건으로 미리 번들에 넣어 둡니다. |
| 치팅 | 서버 검증이 없으므로 점수 상한 같은 클라이언트 쪽 검증만 합니다. 대신 경쟁 요소(리더보드)에 보상을 걸지 않습니다. 포인트 정책상으로도 금지입니다. |

## 5. 마케팅·그로스

- **타깃**: 1순위는 3~8년 차 사원·대리(27~34세)로, 출퇴근 지하철에서 토스를 여는 사람들입니다. 2순위는 중간관리자로, 셀프 디스와 "나도 저랬지" 하는 향수에 반응합니다.
- **메시지**: 근무 태만이 아니라 **'숨 돌리기의 쾌감'**을 앞세웁니다. 예: "오늘도 무사히, 몰래 퇴근."
- **이름 후보**: 몰래퇴근(검색에 유리, 1순위), 눈치사원(캐릭터 IP로 키우기 좋음), 칼퇴작전, 오늘도 무사히
- **서버 없는 바이럴 장치**

| 장치 | 내용 |
|---|---|
| 결과 카드 공유 | 클라이언트에서 도트 이미지를 생성합니다. 예: "오늘 의심도 12% · 칭호: 투명인간 대리" |
| 칭호 밈 | 신입(들킴) → 눈치 9단 → 투명인간 → 전설의 칼퇴왕 |
| 공유 리워드 | 친구가 들어오면 보상을 줍니다. 기준은 반드시 **공유 완료**로 둡니다(결과 기준 금지). |
| 주간 리더보드 | 토스 게임센터 리더보드를 씁니다. 예: "이번 주 최장 연속 칼퇴" |
| 날짜 이벤트 | 매주 월요병·불금 칼퇴, 연말 회식, 명절 전날 조기 퇴근, 1~2월 연말정산(토스 맥락과 연결됨) |
| 푸시 | 금요일 17:30 "칼퇴 시뮬레이션 하실래요?" 정도로, 빈도는 최소화합니다. |

## 6. 실행 계획

### 6-1. 팀과 비용 [추정]
| 역할 | 형태 | 비고 |
|---|---|---|
| PM·기획·QA·운영 | 본인 | 전 기간 |
| 클라이언트 개발 (Phaser/TS) | 외주 1명 | 약 7주 |
| 도트 디자이너 | 외주 1명 | 4~5주, 파트타임 |
| 사운드 | 라이선스 에셋 구매 | - |

**개발비 범위**: 저 약 1,000만 / 중 약 1,700만 / 고 약 2,800만 원. **상한은 1,500만 원 안팎으로 관리할 것을 권장합니다.** 홀드/떼기 방식을 채택했으므로 에셋 비용은 '저~중' 구간으로 예상합니다.

### 6-2. WBS (8주 기준, 압축하면 6주, 완충을 두면 10주)
| 주 | 주요 작업 | 산출물 |
|---|---|---|
| W1 | 핵심 루프·데이터 테이블 정의. **사업자 등록·등급분류 착수.** SDK 3.x 환경 구성. 아트 스타일 가이드(16px 타일) 확정 | 회색 박스 프로토타입 |
| W2 | 홀드/떼기 + 의심 게이지 엔진, 상사 전조·페이크 구현. 플레이어·상사 스프라이트 | 핵심 루프 |
| W3 | 이벤트 3종(커피·화장실·퇴근), 하루 진행. 사무실 타일셋 | 알파 |
| W4 | 저장, 광고(보상형·전면) 연동. UI·결과 화면 | 수익화 포함 알파 |
| W5 | 이벤트 3종 추가(낮잠·쇼핑·간식), 승진·도감·튜토리얼, 결과 카드 공유 | 베타 |
| W6 | 실기기 QA, 최적화(첫 판 진입 3초 이내, 초기 번들 2MB 목표). 등급분류 완료 확인 | RC |
| W7 | 콘솔 등록·검수 제출, 피드백 대응 | 검수 통과 |
| W8 | 출시, 지표 세팅, 핫픽스 | 출시 |

### 6-3. KPI와 Go/Kill 기준 (출시 4주 시점에 판단) [추정]
세 검토의 기준을 하나로 맞췄습니다.

| KPI | Kill | 개선 | Go (2차 투자) |
|---|---|---|---|
| D1 리텐션 | < 20% | 20~30% | ≥ 30% (기획 목표 35%) |
| D7 리텐션 | < 5% | 5~10% | ≥ 10% |
| 1인 일평균 판수 | < 3판 | 3~5판 | ≥ 5판 |
| 보상형 광고 시청률 (DAU 대비) | < 15% | 15~30% | ≥ 30% |
| ARPDAU | < 5원 | 5~15원 | ≥ 15원 |
| 결과 공유율 | 참고 지표 | | |

- **Kill 규칙**: D7과 광고 시청률 중 2개 이상이 Kill 구간이면 신규 투자를 중단하고 방치 운영으로 돌립니다. 운영비가 0원이므로 서비스는 유지할 수 있습니다.
- **Go 시 2차 범위**: 이벤트 6종 추가, 순찰형 상사·고자질 동료, 코스메틱 IAP, 배너, '오늘의 출근' 데일리 시드, 시즌 이벤트

## 7. 리스크와 대응

| 리스크 | 가능성 | 대응 |
|---|---|---|
| **수익 미달** | 높음 | 저비용 MVP로 시작하고 4주 Go/Kill 규칙을 적용합니다. 서버 0원 구조라 방치 운영이 가능합니다. |
| 노출 부족 (미니앱 1만 개 이상 [확인]) | 중~높음 | 추천 미니앱 UX 원칙을 지키고, 2026-10 변경된 노출 기준을 확인합니다. 토스 홈 광고는 소액으로 테스트합니다. |
| 등급분류 지연·명의 불일치 | 중 | W1에 착수하고 명의를 통일합니다. |
| 검수 반려 | 중 | 완충 1주를 둡니다. iframe을 쓰지 않고, 광고 위치와 등급 표시 규칙을 지킵니다. |
| 직장 비하·갑질 묘사 | 중 | 상사는 **귀엽고 허당인 캐릭터**로 그립니다. 폭언·성희롱·외모 비하는 배제하고, 성별·나이 고정관념도 피합니다. |
| 흡연·음주 미화 | 중 | 흡연실은 옥상 바람쐬기로, 술은 건배 턴으로 추상화합니다. |
| 실존 IP·상표 | 중 | 가상 회사명(예: ㈜눈치상사)을 씁니다. '일하는 척' 화면은 특정 제품이 아닌 **일반 스프레드시트 형태**로 그립니다. 외주 계약에 저작권 양도를 명시하고, CC-NC 에셋은 쓰지 않습니다. |
| 반복 피로 | 중 | 이벤트마다 조작을 바꾸고(리듬·타이밍·스와이프), 수정자와 직급별 결 변화를 넣습니다. 1판은 90초 상한입니다. |
| 억울한 실패 | 중 | 전조는 반드시 표시하고 페이크 확률에 상한을 둡니다. 들킨 직후 0.5초 리플레이를 보여 줍니다. |
| 수수료·SDK 정책 변경 | 중 | 출시 전에 요율을 확인하고, 광고 중심 BM으로 결제 의존도를 낮춥니다. SDK 공지를 구독합니다(3.x 강제 전환 전례 있음 [확인]). |
| 저장 데이터 유실 | 저 | 미리 고지하고, 진행도 부담이 작은 설계로 갑니다. 광고 제거 IAP의 복원 방식은 확인이 필요합니다. |
