## 3. 구현한 실험과 특이사항

**상품 총량만 검사해서는 부족하다.** 전체 수량이 증가해도 기존 provider·category·provider×category 집합의 상품이 사라지면 후보를 거부한다. Source의 교차 fixture는 provider/category 총계가 유지돼도 특정 쌍5→3을 만들어 이 경계를 검증했다. 선언 수량이 정상이어도 실제 배열/SQL 행/내용 digest가 다르면 활성 카탈로그로 승격하지 않는다.

**롤백 ID만 비교하면 오래된 후보가 다시 유효해질 수 있다.** Lead는 R1에서 만든 후보→R2 활성화→R1 롤백 뒤 같은 token/parent ID만 검사하는 ABA 설계 위험을 발견했다. 계약과 구현에 영속 상태 세대를 추가했고, 활성화/롤백마다 증가한 세대가 stage 때와 다르면 거부한다. 이 위험은 실제 실패 코드 실행 전에 보강한 설계 항목이며 과거 실서비스 버그의 원인으로 단정하지 않는다. 독립 테스트는 해당 순서와 같은 ID rollback 뒤 오래된 후보 거부를 확인했다.

full완료·선언/실제 count·명시 model/variant identity·기존 baseline·strict 타입/64bit 범위를 검증한다. delta/부분 응답은 이 좁은 PoC에서 안전하게 거부하며 지원 완료로 표시하지 않는다. 별도 SQLite 연결의 두 thread가 동시에 같은 parent를 승격하면 정확히 하나만 commit한다. 실제 SQL trigger로 저장 실패를 주입해 release/offer/active pointer/epoch가 부분 반영되지 않음을 확인했다.

롤백은 카탈로그 참조만 복구한다. 현재 provider권리 철회·alert OFF·favorite삭제·계정삭제 tombstone·동의철회는 유지한다. LKG가 stale/future/TTL경계면 과거값은 보존하되 `current_price=None`, 알림후보=False로 처리한다. 이는 실제 개인정보 삭제나 OS push 발송·가격하락 증명의 검증이 아니다.

## 5. QA와 Lead 판정

독립 QA는 동결된 계약·구현·테스트 hash의 **합성 SQLite 실험 범위 수용**으로 판정했다. 이 범위의 확인된 미해결 구현 결함은 없으며 제품 P0/P1 결함0건을 판정한 것이 아니다. Lead는 계약/실제 SQL transaction·epoch/현재 overlay 구현, demo실행, source/loghash·테스트 참조를 별도로 확인했다. 작성자가 자기 구현을 QA 승인하지 않았다.

관련 원문11행의 RTM에는 `technical_poc_evidence/scope`만 추가했다. 제품 구현·시험·qa_state·final_review는 승격하지 않았고 [부분 추적7개](../governance/POC_REQUIREMENT_TRACE.csv)에 실험에서 검증한 부분/미충족 원문 범위를 함께 기록했다.

## 6. 미완료·위험·네트워크 특이사항

수량비율0.8/0.7과 TTL3600은 **미승인 합성 시나리오값**이다. 실공급처 API/권리/완결성, 운영PostgreSQL·검색세대·분산 lease/네트워크분할·운영부하·RBAC/실삭제/백업/알림발송·실제canonical매칭/이미지·Provider오류율/운영자알림·주요기기/UI는 미검증이다. 위험R02/R15의 방어는 PoC에서 확인했으나 운영 위험을 해제하지 않는다.

2026-10-12 환경 관측은 running/current=true이나 runtime `allowed_hosts=[]`, network state=unknown이었다. 필요한19개 조사도메인은 draft revision3에 저장되어 있고 startup도 저장돼 있지만 runtime 적용/환경 발행은 되지 않은 상태다. [재개 관측](../research/NETWORK_RESUME_OBSERVATION_2026-10-12.json)에 근거를 기록했다. 정책의 의미있는 변화가 없어 같은 차단요청을 반복하거나 proxy/TLS를 우회하지 않았다. 공급처·경쟁·가격·스토어 조건은 계속 미검증이다.

## 7. 승인 경계와 다음 실행

Gate A는 공식 근거/원자 정책·수용 기준 검수 보강 후 판정한다. Gate B 실제 디자인/프로토타입·사용자 승인 전 주요 화면 본격 구현을 하지 않는다. Gate C~F, 제품 독립 QA, 사업/법적·스토어·출시 승인은 미충족이며 **HOLD 유지**다.

현재 외부 필요조치는 환경 설정의 저장된 조사도메인/재개 draft를 검토·저장한 뒤 환경을 발행하는 것이다. 적용 확인 후 동일한 공식 요청을 재검증하고 Phase 1의 권리/요금/시장 근거를 보강한다. 실제 SDK/서비스 실행은 ADR·기술PoC 필요에 따라 따로 준비하고 검증한다. 사용자 자격증명 값은 채팅에 요청하지 않는다.

검증된 PoC 명령을 포함한 `start_skill`을 [재개 지침](../operations/START_SKILL.md)대로 다시 저장했고 [2026-10-12 저장 응답](../research/START_DRAFT_SAVE_2026-10-12.json)을 보존했다. install_script·network·repository membership·secrets는 이 저장에서 변경하지 않았다. 마지막 환경 재관측도 current=true / runtime허용목록빈값이므로 draft저장과 runtime적용/발행을 구분한다.

재개 명령은 저장소 루트에서 `python3 tools/run_catalog_poc.py`와 `python3 tools/validate_project.py`다. [PROJECT_STATE](../../PROJECT_STATE.md), [NEXT_ACTIONS](../../NEXT_ACTIONS.md), [QA_STATUS](../../QA_STATUS.md)에 범위/미완료를 지속 기록했다. 실제 작업이 끝난 뒤 백그라운드에서 계속한다는 의미는 아니다.

## 검증 설계

모든 데이터는 테스트가 생성한 합성 offer이며 임시 SQLite DB에서만 쓰기한다. 선언 수량과 실제 배열 길이 불일치, 최초 baseline·명시 bootstrap, 손실·불완전 full·미지원 delta, 전체 증가 속 특정 provider/category 소실, 경계 비율, 부정 가격·bool·중복 identity, 모델/옵션 분리, 관측시각과 TTL 경계를 검사한다. 실패 시 정상 활성 포인터와 읽기 데이터가 유지되는지 함께 확인한다.

활성화·롤백은 expected parent와 persisted fencing을 검사한다. 독립 DB connection의 두 실제 thread가 barrier 뒤 동시에 동일 parent를 활성화하며 정확히 한 worker만 성공해야 한다. `sleep`, skip, expected-failure, force-pass로 통과시키지 않는다. SQL trigger가 실제 transaction을 중단시키는 실패 주입과 DB 재열기를 통해 상태 보존을 검증한다. Lead가 지적한 ABA 설계 위험도 계약 addendum으로 고정하여 R1→R2→rollback R1 뒤 이전 candidate의 재활성화를 거부하는지 검사했다. 이미 active인 동일 ID로 rollback해도 epoch가 증가하여 이전 candidate를 무효화한다.

권리 철회와 최신 사용자 설정은 release 외부의 현재 상태로 취급한다. 롤백 후 철회 provider 노출·현재 가격·알림 자격을 차단하고 alert OFF·탈퇴·동의 철회가 되살아나지 않는지 확인한다. 미래 시각·오래된 LKG에서 과거 가격은 현재 가격이나 알림 자격으로 승격하지 않는다. 알림 자격 검사는 실제 가격 하락 계산·큐·송신 검증이 아니다.

최초 실패의 두 error는 동일 테스트의 bootstrap False/True subcase에서 발생했다. 손상 fixture가 active release 행을 지운 뒤 QA가 `active_release_id()`로 pointer를 관측했는데, guard가 올바르게 `BASELINE_INVALID`로 거부했다. stage/bootstrap의 거부 자체는 예상대로 동작했다. ## 판정과 남은 범위

독립 검수의 결론은 **동결된 계약·구현·테스트 hash의 격리 실험 범위 수용**이다. 이 실행 범위에서 확인된 미해결 구현 결함은 없으며 최초 테스트 관측 오류는 해결됐다. 작성자 자체 demo 성공으로 QA 통과를 대체하지 않았고, QA는 구현·계약·공급 fixture를 수정하지 않았다.

이 PoC는 실제 offer 행 수와 명시 모델/옵션 identity를 다루며 서비스 전체 15개 엔터티·canonical 매칭·전체 품질 Gate의 완료를 입증하지 않는다. delta는 지원 대신 안전하게 거부한다. 원문 6.6의 이미지 정상률·Provider별 오류율·운영자 알림, 공식 공급처의 완결성/권리/TTL, PostgreSQL·검색 세대·분산 lease·운영 부하·백업·삭제 sink·RBAC·실제 가격하락 및 전달·주요 여정·실기기는 미검증이다. 단일 합성 favorite boolean은 실제 상품별 찜 관계 검증도 아니다.

생산 임계값·TTL은 미승인이며 Gate A~F 통과나 사용자 Gate B 승인·출시 승인을 추가하지 않는다. 제품 독립 QA **Not Started**, 공식 출시 **HOLD**는 유지한다. 다음 운영 설계/PoC는 실제 공급처 계약·샘플, 운영 DB·검색·분산 모델, 상세 수용 기준과 별도 독립 검증이 필요하다.

## 8. 광고·제휴 수익 방향과 마케팅 50,000원

[Monetization Plan](../growth/MONETIZATION_PLAN.md)은 클릭/주문전환·예상/확정 수수료·반품/정산을 구분한다. 공급처가 전환을 제공하지 않으면 클릭을 구매 실적으로 만들지 않는다. 광고는 식별되는 슬롯·빈도/동의·미충족/미노출 상태를 갖고 구매 이동을 막지 않는다. eCPM/수수료/요청 fill은 확인 전 실제 단가로 사용하지 않는다.

[Marketing Plan](../growth/MARKETING_PLAN.md)은 유기적 콘텐츠/SEO/ASO와 승인형 소액 실험을 우선한다. 도구 구독·콘텐츠·광고·예비비를 포함하여 월 50,000원 이내로 제안한다. 실제 지출/외부 게시/광고 집행은 0이며 집행은 별도 승인 대상이다. MAU별 수익·원가·민감도 표는 가정 시뮬레이션이며 매출 예측 확정이나 실제 사용자 KPI가 아니다.

## 9. 기술·환경·비용·보안

[ADR 후보](../architecture/ADR-001-STACK-CANDIDATES.md)는 Flutter, React/Next.js Admin, 경량 API, PostgreSQL/저비용 관리형 Backend의 비교안이다. 기술은 **Proposed**다. 현 Linux 환경에서 Git/Python/Node/Docker는 관측했지만 Flutter/Android/iOS/PostgreSQL 앱 환경을 설치·실행하지 않았다. iOS RC는 macOS/Xcode/서명·스토어 권한이 필요한 별도 환경 조건이다.

[Cost Model](../operations/COST_MODEL.md)은 MAU 및 상품 10,000/100,000/500,000/1,000,000 규모별 부하/원가 입력을 분리한다. 공식 요금 접근은 차단되어 단가/무료 구간은 확정하지 않는다. 전체 인프라 월 상한도 사용자 결정 대상이다. 유료 서비스·프로젝트 생성/배포는 없었다.

[Security Plan](../security/SECURITY_PRIVACY_PLAN.md), [Data Inventory](../security/DATA_INVENTORY.md), [Release Hold](../security/RELEASE_HOLD_CHECKLIST.md)는 선택 월령 구간/메모리 세션 기본·아이 이름/정확한 생일/사진 미수집, 최소권한·MFA/감사·고위험 2인 승인, open redirect/SSRF/서명·replay/secret·탈퇴/백업복구 후 재삭제 등을 검수 대상으로 한다. 기기 영속화·계정 동기화는 OFF인 별도 선택 제안이며 법률/스토어/실제 보안 테스트 완료는 아니다.

## 10. 실제 검증 증거와 결과

| 범위 | 실제 수행/증거 | 결과 한계 |
|---|---|---|
| 신규 저장소/환경 | git status, 원격 읽기, 버전/리소스 관측 | 기본 사용 가능, 제품 SDK/앱 검증 아님 |
| 기존 프로젝트 | pinned commit/파일·카탈로그 이력 parser/guard 읽기 | 파일 수량 감소 확인, API 원인·실사용 영향 미확인 |
| 공급처/경쟁/스토어/요금 공개 문서 | TLS/프록시 유지한 읽기 요청·오류 JSON | CONNECT 차단, 원본 페이지/계약/요금 미확인 |
| 접근성/폰트 공식 저장소 | W3C 소스 5개·폰트 라이선스 2개 HTTP 200 원문 저장 | published 표준 직접 확인/제품 접근성 통과가 아님 |

| 가정 수익/예산 산술 | `python3 tools/revenue_model.py` | 최종 실제 산술 검증은 [MODEL_VALIDATION](../growth/MODEL_VALIDATION.json), 시장 검증 아님 |
| 독립 초기 검수 | 별도 QA의 [Initial Review](../qa/INITIAL_REVIEW.md) | 문서/추적·상태 검수, 제품 QA/사용자 승인 아님 |
| 제품 기능/빌드/데모/RC | 실행 안 함 | Not Started, 성공/실패 수로 보고하지 않음 |

실행 결과는 파일 확인 전 통과로 단정하지 않는다. 자기가 만든 문서를 QA 승인하지 않으며 실패 수정은 원 담당에 반환한다.

## 11. QA·릴리즈 Gate와 Lead 검수

[TEST_PLAN](../qa/TEST_PLAN.md)과 [QA_STATUS](../../QA_STATUS.md)를 따른다. Gate A는 요구사항/정책/범위/RTM 정합성, B는 사용자 승인된 UX/UI, C는 아키텍처/공급처/비용/보안, D는 구현·정적/단위/통합·시각/RTM, E는 독립 QA·핵심 여정·실데이터·기기·보안/성능과 P0/P1 0, F는 RC/운영/롤백/법적·스토어/사용자 출시 승인이다.

독립 QA는 초기 문서 제출 수준으로 수용했다. P2 문서 결함3건(원문 ID 형식, 경쟁 조사 축 수, Backend의 오래된 충돌 설명)은 원 담당 수정 후 독립 재검토로 해결됐으며 해당 문서 검수 범위의 미해결 확정 결함은0건이다. 제품 P0/P1 결함0건이나 기능 QA통과 판정은 아니다. 원문/RTM/링크/ID/HOLD 검사913/913행 통과와 가정수익15행/민감도135행 재현12검사는 각각 기록했다.

Lead는 초기 산출물의 원문·담당·상태·실행 근거와 QA 반환 수정을 별도로 확인했고 [LEAD_REVIEW](LEAD_REVIEW.md)에 실제 대조 범위를 남겼다. 현재 Gate A 전체 통과나 Gate B 이후 단계 완료는 선언하지 않는다. 출시 HOLD는 유지한다.

## 12. 미완료·이슈·위험 대응

공식 시장/공급처/스토어/요금 조사는 접근 차단으로 미완료다. 사업자등록·제휴/이미지/데이터 권한·인프라 예산·OAuth 계정·macOS/서명 권한도 미확인이다. 경쟁 화면·Figma·실제 프로토타입·앱/API/Admin/파이프라인·실데이터·제품 QA·스토어 후보는 이후 Gate에 남아 있다. [RISK_REGISTER](../../RISK_REGISTER.md)에서 책임/예방/해제 근거를 확인한다.

## 13. 사용자 승인/조치가 필요한 항목

**지금 필요한 외부 조치는 공식 조사 도메인 적용이다.** 환경 설정 draft에 필요한 19개 공개 공식 도메인을 저장했으며 `status=saved`, `requires_publish=true` 응답을 확인했다. 환경 설정에서 검토·저장한 뒤 환경을 발행해야 한다. 저장만으로 runtime 허용이 적용됐다는 뜻은 아니며 적용 후 동일 요청을 재검증한다. 무제한 인터넷·자격증명·유료 사용 권한은 요청하지 않았다.

저장 응답과 19개 도메인은 [NETWORK_DRAFT_SAVE](../research/NETWORK_DRAFT_SAVE.json)에 보존했다. 실제 실행해 확인한 문서/수익 검사와 상태 파일 재개 순서는 `start_skill`에도 저장했고 [START_DRAFT_SAVE](../research/START_DRAFT_SAVE.json)와 [지침 원문](../operations/START_SKILL.md)에 연결했다. 외부 패키지 설치가 필요 없어 `install_script`는 변경하지 않았다. 저장은 현재 instance 실행이나 환경 발행을 대신하지 않는다.

나머지 결정 카드는 [DECISIONS](../../DECISIONS.md)에 있다: 선택 빈 원격을 계속 쓸지, 인프라 월 상한/사업·제휴 준비 상태, 로그인·개인정보 범위, 실제 시안 검수 후 핵심 UX 방향. [요구사항 충돌/미결정 분석](../governance/REQUIREMENTS_REVIEW.md)도 함께 확인한다. 기존 실패 프로젝트는 참고만 사용한다는 지시는 이미 반영되어 재확인하지 않는다. 현재 Phase 3 산출물이 없으므로 Gate B 승인을 미리 요청하지 않는다.

## 14. 다음 실행과 확인 방법

본 보고서→README의 각 문서→RTM 원문 행→실제 근거 JSON/QA 결과 순서로 검수할 수 있다. Markdown은 로컬 파일로 열람하고 CSV는 표 도구로 확인할 수 있다. 공개 데모/원격 PR/CI 링크를 만들어내지 않았다.

[NEXT_ACTIONS](../../NEXT_ACTIONS.md)는 조사 접근 재검증→Phase 1 사실 보강→세부 원문/정책/수용 기준 QA→Gate A→UX/디자인 검수/사용자 Gate B→설계/구현을 지정한다. 재개를 위한 문서/명령은 저장하지만 현재 실행 종료 뒤 백그라운드 작업을 계속한다는 뜻은 아니다.
